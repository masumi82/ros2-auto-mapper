# 探索アルゴリズム詳細

`auto_mapper/auto_explorer.py`(約400行)の中身を解説します。

## 3段構えの探索戦略

### 第1段: フロンティア探索
- `/map` の「床セル(free)と未知セル(unknown)が隣接する境界」= フロンティアを列挙
- 連結成分でクラスタリングし、`min_cluster`(既定4)未満のノイズを捨てる
  - 狭いドアの縁に出る1〜2セルの偽フロンティアで無限往復するのを防ぐ
- ゴールは**クラスタ重心ではなく境界セルの近傍**で安全な床を探して置く
  - 巨大な弧状クラスタは重心が未知空間に落ちてゴール探索が空振りするため

### 第2段: LiDARレイ・フォールバック(ユーザー発案)
フロンティアが尽きても、LiDARの射程(3.5m)を素通りする方向=まだ壁を見つけて
いない方向が残っていることがある。

- 360本のレイを5本窓の移動平均で平滑化し、最遠方向を選ぶ
- その方向へ `step = min(最遠距離 - 0.5, 2.0)` メートル前進するゴールを出す
- 最遠でも1.2m未満なら「見るべき方向は残っていない」としてNone

### 第3段: 放浪(wander)モード
LiDAR射程内に反射物がない大空間では、SLAMは遠隔からは地図を拡張できない
(エコーのないレイは破棄される)。**実際に走って行くしかない**。

- フロンティアもレイもNoneのとき、盲目的に前進ゴールを3連続で出す
- 1巡の成長が60セル未満 ×2回連続で「本当に描き尽くした」と判定

## 失敗処理: 成長ベース・ブラックリスト

到達失敗したゴールを永久ブラックリストにすると、一時的な障害(狭通路での
タイムアウト等)でエリアごと餓死する。逆にブラックリストなしだと同じ場所への
到達失敗ループに陥る。

採用した折衷案:
- ナビゲーション結果が **status=4(成功)でない かつ 試行中の地図成長 < 30セル** の
  ゴールだけをブラックリストに入れる
- 「失敗したが地図は伸びた」場所は再挑戦の価値があるので入れない

## 完成判定(三重チェック)

```
フロンティアなし(min_cluster以上のクラスタが0)
AND 素通りレイなし(最遠方向 < 1.2m)
AND 放浪しても成長しない(60セル未満×2巡)
→ 完成 → slam_toolbox/save_map で自動保存 → 終了
```

## 既知の制約

1. **細い廊下のフロンティアは拾えない**
   境界セル近傍の安全な床(クリアランス)探索が、幅0.8m級の廊下では失敗する。
   → `scripts/corridor_march.py` でNav2に直接ゴールを送り廊下を突破してから
   探索を再開する運用でカバー(突破後は普通のフロンティア探索が機能する)。
2. **廊下エイリアシング**
   特徴の少ない細長い空間ではスキャンマッチングが滑り、自己位置がずれて
   地図がゴースト化することがある。ずれの検証は「SLAMのTF(map→base_footprint)」と
   「Gazeboの真値(gz model -p)」の同時刻比較で行う。
3. **転倒リスク**
   inflation_radius=0.15では壁・家具スレスレを走るため、家具に乗り上げて
   転倒することがある。転倒後に手動で正立させると車輪が回らずに移動した分が
   odomに残留誤差(実測~0.4m)として残る点に注意。

## パラメータ

| パラメータ | 既定値 | 意味 |
|---|---|---|
| `min_cluster` | 4 | フロンティアクラスタの最小セル数 |
| `max_goals` | 60 | 1回の実行で出すゴール数の上限 |
| `map_save_name` | - | 完成時の保存先(pgm/yamlのベース名) |
| `use_sim_time` | true | シミュレーション時刻の使用 |

## Nav2側の重要設定(config/nav2_params_explore.yaml)

| 設定 | 値 | 理由 |
|---|---|---|
| `track_unknown_space` | false | 未知領域を通行可能扱いにし、未知への経路計画を許す |
| `inflation_radius` | 0.15 | 0.55のままだと幅0.8mの廊下が通行不能(0.55×2>0.8) |
| `robot_radius` | 0.22 | 車体サイズ由来。安全性はこちらで担保 |
