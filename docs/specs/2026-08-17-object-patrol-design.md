# 設計書: 物体探索パトロールロボット「object_patrol」

- 日付: 2026-08-17
- ブランチ: `feature/object-patrol`
- 前提プロジェクト: 自動地図化ロボット(auto_mapper) — 本リポジトリ main ブランチの成果物

> **実装時の改訂(2026-08-17)**: 統合検証の実測に基づき以下を変更した(経緯と根拠は
> `docs/object_patrol_result.md` のチューニング表を参照)。
> §4② 信頼度しきい値 0.6 → **0.5** / §4③ LiDAR距離は中央値 → **最近傍値**、
> 統合距離 0.5m → **0.8m**、確定 3 → **4フレーム** / §4① 見回し回転 → **0.25 rad/s**。
> §4③ 床平面フォールバックは未実装(最近傍値化で基準達成のため)。

## 1. 目的

前回作成した家の地図を再利用し、ロボットが各部屋を自律巡回しながら
カメラ映像を YOLO で解析して物体(人・椅子・ボトル等)を発見し、
その位置を地図上に記録する。最終成果物は「どこに何があったか」を示す物体マップとレポート。

学習テーマ:

- 既知地図の再利用と自己位置推定(map_server + AMCL)
- 画像認識パイプライン(camera → cv_bridge → OpenCV → YOLO)
- カメラ + LiDAR のセンサーフュージョンと TF 座標変換
- トピック / サービス / アクションの 3 通信方式を 1 システム内で実践

## 2. スコープ

- 対象環境: WSL2 + ROS 2 Humble + Gazebo Classic(シミュレーションのみ。実機は対象外)
- ロボット: TurtleBot3 **waffle_pi**(カメラ搭載モデル。前回の burger から変更)
- ワールド: 前回の密閉 TB3 ハウス(封鎖壁・ドアプラグ入り)+ YOLO 認識対象の物体モデルを各部屋に配置
- 地図: 前回の自動地図化で生成した `maps/` の家地図をそのまま使用
- YOLO: YOLOv8n(最軽量モデル)を CPU 推論。GPU は使わない

### スコープ外(YAGNI)

- 未知環境の同時地図化(SLAM との同時実行)
- 物体への接近・把持などのマニピュレーション
- 実機(ラズパイ + USB カメラ)への展開 — 将来の別プロジェクト

## 3. 全体アーキテクチャ

```
Gazebo(密閉ハウス + 物体モデル)
  │ /scan  /camera/image_raw  /odom
  ▼
map_server(既知地図配信) ──▶ AMCL(自己位置推定、TF: map→odom)
  ▼
Nav2(経路計画・走行) ◀──(アクション: NavigateToPose)── patrol_node【自作①】
                                                        │(サービス: 集計指示)
yolo_detector【自作②】──(トピック: /detected_objects)──▶ object_mapper【自作③】
                                                        ▼
                                              物体マップ PNG + レポート
```

自作ノードは 3 つ。1 ノード 1 責務で分離する。

## 4. 自作ノードの責務

### ① patrol_node(巡回管理)

- 巡回ポイント(waypoint)を YAML(`config/patrol_points.yaml`)で定義。各部屋 1〜2 点
- NavigateToPose アクションで waypoint を順に走行
- 各 waypoint 到着後、その場で 360° 回転して部屋全体をカメラで見回す
- 全 waypoint 完了後、object_mapper へサービス呼び出しで集計・出力を指示
- ABORT 時は当該 waypoint をスキップして次へ(リトライ 1 回)

### ② yolo_detector(画像認識)

- `/camera/image_raw` 購読 → cv_bridge → YOLOv8n 推論
- 推論は 2〜3 fps に間引き(巡回速度では十分。WSL2 の CPU 負荷対策)
- 出力: 独自メッセージ `DetectedObjects`(クラス名・信頼度・バウンディングボックス・画像タイムスタンプ)を `/detected_objects` に配信
- デバッグ用に検出枠描画済み画像を `/detection_image` に配信(RViz で確認可能)
- 信頼度しきい値 0.6 未満は破棄

### ③ object_mapper(位置推定・記録)— 本プロジェクトの核心

LiDAR フュージョンによる位置推定手順:

1. バウンディングボックス中心の横ピクセル位置と水平画角(約 62°)から方位角 θ を算出
2. `/scan` の θ 方向 ±数度の距離値の中央値を採用(ノイズ除去)
3. (θ, 距離) → ロボット座標系の点 → TF で map 座標系へ変換
   - 変換には検出画像のタイムスタンプ時点の TF を使用(移動・回転中のずれ防止)
4. 既存登録物体と同一クラスかつ距離 0.5 m 以内なら同一物体として統合(位置は平均更新)。それ以外は新規登録
5. 新規登録は「同一物体を 3 フレーム以上観測」してから確定(誤検出抑制)

出力:

- リアルタイム: RViz マーカー(`/object_markers`)で発見物体を地図上に表示
- 終了時: 物体アイコン入り地図画像(PNG)+ レポート(クラス別の個数・座標一覧、Markdown)

### フォールバック(細足物体対策)

LiDAR 高さ(16 cm)に実体がない物体(椅子の細い脚など)は θ 方向の距離が壁までの距離になる。
対策: θ 方向の距離が「バウンディングボックス下端 + 床平面仮定から推定した距離」と大きく食い違う場合、床平面仮定の値を採用する。

## 5. 通信方式の使い分け(学習ポイント)

| 通信 | 使用箇所 |
|---|---|
| トピック | カメラ画像、/detected_objects、RViz マーカー |
| サービス | patrol_node → object_mapper の「巡回完了、集計せよ」 |
| アクション | patrol_node → Nav2 の NavigateToPose |

## 6. 検証条件(完成の定義)

- 家の中に YOLO が得意なクラスの物体を 5 種類程度・計 6〜8 個配置(person, chair, bottle 等。フェーズ 1 の静止テストで認識可能なモデルを最終選定)
- 成功条件: **配置物体の 8 割以上を発見し、位置誤差 0.5 m 以内で記録**
- 誤検出(存在しない物体の登録)ゼロを目標。しきい値 0.6 + 3 フレーム確認で抑制

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| WSL2 での YOLO CPU 推論が重い | YOLOv8n + 2〜3 fps 間引き。不足なら入力解像度を 640→416 に縮小 |
| Gazebo 標準モデルの CG 感で YOLO が認識しない | フェーズ 1 の静止認識テストで可否確認し、認識可能なモデルのみ採用 |
| LiDAR 高さに物体の実体がない | 実体がある物体を優先配置 + 床平面仮定フォールバック(§4③) |
| AMCL の初期位置ずれ | スポーン座標を initialpose トピックで与える(前回の知見を流用) |
| 回転中の検出で位置がずれる | 画像タイムスタンプ時点の TF で変換 |

## 8. 実装フェーズ

1. **静止認識テスト**: waffle_pi の目の前に物体を置き、YOLO の認識可否を確認。採用モデルを確定
2. **既知地図での走行**: map_server + AMCL + Nav2 で地図上の 1 点へ走行できることを確認
3. **巡回**: patrol_node で全部屋巡回 + 各点 360° 回転
4. **フュージョン**: object_mapper で位置推定・マーカー表示・重複統合
5. **統合実行 + エビデンス**: 通し実行、成功条件判定、スクショ・動画記録

各フェーズは前のフェーズの動作確認後に着手する(前回の教訓: 実測 > 机上計算)。
